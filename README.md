## 题目要求回答的四个问题（4.5.3）

### 1. 本次任务中使用了哪些 Git / GitHub 功能？

- `git init` 初始化本地仓库，`git clone` 拉取远端仓库到本地；
- `git status` / `git diff` 查看工作区与暂存区的改动，确认每次提交的内容；
- `git add`（按目录分批添加）+ `git commit -m` **分次提交**：先提交"内训选题初稿"，再提交"幻灯片与 README"，避免最后一次性上传全部文件；
- `git log --oneline` 查看提交历史，必要时 `git checkout -- <file>` 撤销改动；
- `git remote add` / `git push` 把本地提交推送到 GitHub 上的远程仓库；
- 了解但本次未强制使用：分支 + Pull Request（多人协作流程，见第 3 问）。

### 2. 操作过程中遇到了哪些问题？如何解决的？

| 问题 | 现象 | 解决办法 |
|---|---|---|
| 中文文件名与路径 | 提交后文件名显示乱码、脚本读不到 | 统一把源文件存为 **UTF-8**；含中文路径的脚本改用 UTF-8 BOM，避免命令行按本地编码解析 |
| 行尾不一致（CRLF/LF） | `git diff` 显示整篇文件都被改动 | 设置 `core.autocrlf`，并在仓库里加 `.gitignore`/`.gitattributes` 统一行尾 |
| 忘记添加文件 | 提交后发现新文件没进去 | 养成 `git status` 再 `git add` 的习惯；按目录分批 `add` 更不容易漏 |
| 大文件与二进制素材 | 图片/pptx 会迅速增大仓库 | 只保留必要的示意图与成品（几百 KB 级），源图压缩后再入库 |
| 提交信息随意 | 历史无法回溯 | 采用"动作 + 对象"格式：如"完成内训选题初稿""添加授课幻灯片并完善 README" |
| 推送失败（网络） | `push` 超时 | 换用 SSH（443 端口）或镜像/代理，重试前先 `fetch` 确认远端状态 |

### 3. 将来多名教学部成员共同维护这个仓库，应如何组织文件与修改流程？

**（1）文件组织约定**

- 一人一目录：`topic/` 按课程分文件、`slides/` 按"课程名-课时"命名，素材统一放 `assets/`，避免各写各的；
- 命名规范：文件名用"**主题-用途**"格式（如 `定时器-课件.pptx`），不带"最终版/新建副本"这类字样；
- 大文件不进仓库：PPT 源文件超过 10 MB 时，改存网盘并在 README 里留链接；
- 每学期末由负责人归档到 `archive/2026-秋/`，保持主目录干净。

**（2）修改流程**

1. 每个改动开一个**分支**（如 `feat/timer-slides`），不在 `main` 上直接改；
2. 分支上小步提交，提交信息写清"改了什么、为什么"；
3. 提交 **Pull Request**，由至少一名其他成员 review（内容正确性 + 排版/链接是否可用）；
4. review 通过后合并到 `main`，`main` 保持随时可用；冲突在分支上解决，不直接改 `main`；
5. 用 **Issue** 记录"待补充的课件""发现的错误"，让任务可跟踪；
6. 定期（如每月）由负责人合并整理并更新 README 的完成情况。

**（3）权限与责任**

- `main` 设为保护分支，禁止直接推送；
- 设 1～2 名"资料负责人"负责合并与归档；
- 新成员先用 Fork + PR 的方式练手，熟悉后再加入协作者。

### 4. 本次纳新题是否使用了 AI 工具？

- **使用了**。AI 参与了以下环节：
  - 内训方案的**结构与措辞打磨**（把零散想法整理成"课程定位 / 学习目标 / 课时安排 / 问题与对策"的结构）；
  - 制作幻灯片时，用 AI 生成 **OOXML/绘图脚本**来排版图表与示意图（示意图、代码图的底图）；
  - 检查**表述与事实**：例如 PSC/ARR 与定时周期的换算、`volatile` 的作用、看门狗参数等，逐条核对；
  - 文字校对（错别字、标点统一、章节编号一致性）。
- **人工检查与修改**（AI 生成后由本人完成）：
  1. 所有技术结论都对照 **STM32F103 参考手册 / HAL 库**核对，并在我自己的 F103 板子（DAPLink + Ozone）上**实际运行验证**（1 ms 定时中断、`tick` 自增、看门狗复位）；
  2. 幻灯片的版式、配色、页序全部手工调整，替换掉 AI 的通用模板风格；
  3. 删除了 AI 生成的笼统套话（如"众所周知""极大地提高了效率"），改成具体数值与可操作步骤；
  4. 示意图与代码图由脚本绘制后逐张检查（箭头指向、公式、引脚名是否正确）。
- 结论：AI 用于**提速与结构整理**，技术正确性、教学内容取舍与最终成稿由本人负责；面试时可就上述任一处细节展开说明。
